# qutansuo-opendev-signup-diff

去探索(qutansuo)报名数据 → OpenDev credits 发放平台的报名同步差集复核 skill。

每次活动快照更新后,以报名表为基准、OpenDev 已建额度人员为辅计算差集,按可演进规则引擎筛除异常/批量注册邮箱,导出可直接导入的极简 Excel。规则逐期积累,新模式经确认后沉淀进规则文件。

## 文件

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 执行流程:输入识别 → 比对口径 → 筛查流程 → 输出规范 → 汇报格式 |
| `rules.md` | 可演进规则引擎:字段映射、R1-R7 异常规则(带版本/日期/来源)、保留原则、历史执行记录 |

## 用法

skill 安装在 ZCode/agents 的 skills 目录(`~/.agents/skills/qutansuo-opendev-signup-diff/`),由 Agent 自动发现。触发方式:对 Agent 说

- 「再处理一遍新增邮箱」
- 「跑一次差集」
- 或在放入新快照(报名表 + hks-activity-data 导出)后提及比对筛查

输入目录约定:`项目/<活动名>/报名数据导入到opendev/`,放两份文件:

- `*报名表*.xlsx`(去探索导出,状态「已通过」行为基准)
- `hongqiao-tech-week-hks-activity-data-<UTC时间戳>Z.xlsx`(OpenDev 导出,用 `people` sheet)

输出:`新增邮箱-YYYYMMDD.xlsx`,双 sheet——「新增邮箱」(序号+邮箱,可直接导入)、「异常已剔除」(序号+邮箱+剔除原因,留底)。

## 规则演进机制

异常规则**不在 SKILL.md 里**,在 `rules.md`。每期执行后:

1. 按现有规则筛查;规则未覆盖的新异常模式先人工核对报名明细
2. 向用户确认后将新规则追加进 `rules.md`(判据 + 版本号 + 日期 + 来源事件)
3. 新活动字段口径不同只改「字段映射」节;历史执行追加到记录表

## 设计要点

- **域名不是判异常依据**:outlook/gmail/自定义域本身不定罪,报名信息具体真实(真实学校、具体获奖经历、可联系微信)即保留;边缘存疑但证据充分的保留并点名
- **邮箱归一匹配**:去空格 + 小写;同一邮箱多条报名取最新一条做甄别
- **防误判**:剔除清单先做 `assert set(R) <= diff` 校验,差集口径变化时立即暴露
- **来源可溯**:每条规则记录产生它的真实事件(如 Ethan×110 批量注册事件),便于复核规则是否仍适用
